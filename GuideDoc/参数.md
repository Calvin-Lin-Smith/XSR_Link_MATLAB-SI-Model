# VLSI2024 XSR 参数台账

本文以 src/config/phyConfig.m 与 gui/D2DWorkbench.m 的 paperConfigPaths() 为准。Typical 指 phyConfig('vlsi2024_xsr_typical')，Ideal 指 phyConfig('vlsi2024_xsr_ideal')；两者都保持 paper.id = VLSI2024_XSR_3nm 和同一 schema。Ideal 是零损耗/零噪声 debug reference，不是另一篇论文或 silicon corner。

表中“训练归属”是 Run x8 Link 的 stage owner。requested 是用户请求，trained 是 stage 训练后的配置，applied 是实际 D2DPHY/leaf 对象接受的值；三者的完整规则和路径见 [Test 回调契约](Test回调.md)。

| txPma.lane.sixTapPreset.coeffs | signed 向量 | [-0.03 -0.05 0.88 -0.06 -0.04 -0.02] | [0 0 1 0 0 0] | 真实论文系数未公开；这里只是可复现候选 | ffeTraining；model-selected |

dspFfeVector(symbols,tapCoeffs,tapOffsets,options) 使用显式 signed FIR。offset < 0 是 pre-cursor，offset = 0 是 main，offset > 0 是 post-cursor；其 meta 返回 raw/applied coefficients、offsets、magnitude sum、constraint、impulseResponse。论文只给出 3/optional 6-tap 架构，不给这些精确系数。

兼容 typical/ideal 仍保留 txEqMain、txEqPre、txEqPost 和 amplitude 字段；VLSI paper profile 因存在 ffeMode/ffeCoeffs，TxLane.configure 优先走 vector FFE，不要把旧 flat 字段当作 paper GUI 控件。

注意 Ideal profile 的 cfg.txPma.lane.ffe 是创建 paper profile 时留下的 nested 快照，可能仍显示 Typical coeffs；实际 consumer 是 flat 的 ffeMode、ffeOffsets、ffeCoeffs，因此 ideal 运行使用 flat [0 1 0]。阅读 config.json 时应把 nested ffe 与 appliedFfe/tapMeta 分开。

## TX driver / SST DAC 行为

|---|---|---:|---:|---|---|

| txPma.lane.dacLevels | integer level | 206 | 206 | >= 2；Ideal requested 仍为 206，但 applied dacMeta.appliedLevels 为 0（量化关闭） | startupCalibration；206 为论文事实 |

量化步长为 2*targetSwing/(dacLevels−1)。仅当 enableDacQuantization=true 时，Driver.dacMeta 才包含 appliedLevels、targetSwing、gainError、swingCalibrated、step、peakBeforeClip、clippedSamples 等量化/校准 metadata；关闭时只保留 enabled=false、appliedLevels=0。206 levels 只表示行为级离散输出；没有实现 7.5-bit SST 分段、电流源、PVT 或功耗。

dspBbCdr 是 reference-free、decision-directed early/late loop：PI 先给 data/edge phase，sampler 产生 early/late，phase detector 用此前 decision 计算 error，再更新 rawCode。lock 需要最近窗口的足够 RX transitions、residual phase 在 tolerance 内、PI code span 不超上限；minTransitions 默认 max(4,ceil(lockWindow/8))，maxCodeSpanCodes 默认 8，二者是函数后台默认而非 GUI 行。

dspPiClock 将 round(rawCode) modulo nCodes，再加入确定性 mismatch，输出 phaseUI、appliedCode、mismatchLSB、wrapCount。论文的“2 DLL + PI + BB-CDR”和 PI < +/-0.5 LSB 是事实；64 code、loop gain、lock window、phase detector 实现是模型假设。

effective CDR = model.debugStages.cdrEnabled AND model.cdrOptions.enabled。两者任一为 false，Run x8 Link 进入 debug_no_cdr，使用 manualPhaseUI/manualDelayUI，不报告 formal BER。

离线训练预算的时间轴为 consumedUI 的累加，trainingEndUI = sum(consumedUI)。它不等于最终链路发送的 sample 数；最终 BER 起点还要等待 latest lane lock 和 postLockWaitUI。

## 论文事实、模型假设与不要混淆的量

- 论文事实：8 lanes + PLL、9.8–113 Gb/s PAM4/NRZ 范围、3/optional 6-tap FFE、7.5-bit/206-level SST DAC、单级 CTLE 0–6 dB/0.2 dB、12 data + 4 edge + 4 spare sampler、2 DLL + PI/BB-CDR、PI mismatch < +/-0.5 LSB、PRBS31、1–80 mm/0.5–10 dB 通道上下文、NEXT/FEXT −40/−38 dB @28 GHz、194 fs PLL+TX integrated-jitter measurement context、0.9 pJ/b quote。
- 模型假设：112.5 Gb/s/56.25 GBd baseline、sps=16、nBits=2^18、SNR/RJ/DJ、analytic IL 的三阶 IIR、CTLE 零点 0.25、FFE 系数、64-code PI、lock criterion、训练预算、level-shift 数值和 adaptation objective。
- 不能把 paper facts 写成 applied result；尤其 0.9 pJ/b 不是功耗预测，194 fs 不是 TX-only jitter，论文 <1e-12/<1e-14 不是有限 BER 输出。
