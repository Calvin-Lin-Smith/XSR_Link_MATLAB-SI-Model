这个工程的核心目标是建立一个面向 D2D 112G PAM4 PHY 的系统级 SI 行为模型。设计思路是自顶向下和自底向上结合：底层先实现 PRBS、PAM4 映射、FFE、信道、CTLE、采样、切片、对齐等纯 DSP 算法；中间层把这些算法封装成 `Blk`、`Ffe`、`Channel`、`Ctle` 等可观测叶子模块；上层再组装成 TX lane、RX lane、TX/RX PMA 和 `D2DPHY` x8 顶层模型。GUI 和 Simulink 都不重新复制一套算法，而是调用同一套 MATLAB 源码。测试脚本负责验证功能和趋势，GUI 负责交互式参数编辑、眼图和测试，Simulink 负责框图化展示，三者通过 `phyConfig` 和共享变量 `d2dCfg` 连接起来。

工程根目录下，`Reference/` 存放设计依据，包括 `Die-to-Die 112G USRXSR x8 PHY for TSMC 12-nm FFC1.8V Databook.pdf`，即原始 Databook；`Reference/databook_text.txt` 是从 PDF 提取的文本版本，方便搜索和整理。`D2D_PHY_SI建模与测试方案.md` 描述总体建模方案、参数台账、风险和测试思路；`D2D_PHY_SI_层级化架构设计.md` 描述 Databook 对齐的层级结构、类之间关系和白盒观测方式；`D2D_PHY_SI_自己动手执行手册.md` 是实际执行手册，包含 MATLAB 命令、目录结构、验收步骤和 T1–T9 任务清单；`功能描述.md` 用于说明模型功能；`参数.md` 用于记录参数含义和配置约定。根目录下的 `gui_1.png`、`gui_fixed.png` 是 GUI 调整前后的截图，属于界面检查资料，不参与模型运行。

`src/` 是工程的核心源码目录，目前按职责分为 `dsp/`、`utils/`、`leaf/`、`composite/` 和 `config/`。所有测试、GUI 和 Simulink 都通过 `addpath(genpath('src'))` 使用这些源码。

`src/dsp/` 存放纯函数形式的底层 DSP 算法。`dspPrbs.m` 生成 PRBS7、PRBS15、PRBS31 和 surrogate PRQS10 等测试码型；`dspMap.m` 把 bit 映射成 NRZ 或 PAM4 电平，PAM4 的电平是 `-3、-1、1、3`；`dspFfe.m` 实现符号率 FFE，包括 main、pre、post 和可选归一化；`dspChannel.m` 实现解析型 D2D 信道，支持 Nyquist 损耗和极点数；`dspCtle.m` 实现一阶 CTLE，利用零点、极点和 boost dB 进行高频补偿；`dspSlice.m` 对 NRZ/PAM4 波形进行判决；`dspSample.m` 按采样相位、UI delay、SPS 和抖动进行采样；`dspAlign.m` 在 TX 参考和 RX 波形之间搜索采样相位与延迟，并计算误码；`dspSample.m` 和 `dspAlign.m` 共同支持 CDR、眼图和 BER 测量流程。

`src/utils/` 存放分析和可视化工具。`plotEye.m` 把一维波形按两个 UI 重叠绘制成眼图；`eyeHeight.m` 根据采样点聚类估计 NRZ 或 PAM4 的眼高；`ffeEqDb.m` 根据 FFE tap 计算 pre/post 等效 dB，用于 P9 公式校验和均衡扫描；`verifyChannel.m` 对正弦信号经过信道后的 Nyquist 损耗进行测量，验证解析信道的 dB 参数是否正确。

`src/leaf/` 存放基础类和最底层硬件功能块。`Blk.m` 是所有模型块的基类，提供名称、配置、输入输出日志、节点记录和 `dump()` 白盒输出能力；`Serializer.m` 实现符号到过采样波形的串化；`Ffe.m` 是对 `dspFfe.m` 的对象封装；`Driver.m` 模拟 TX driver 幅度和输出；`Term.m` 模拟 RX 端接和增益；`Ctle.m` 是 CTLE 对象封装；`Deserializer.m` 把采样后的符号组织回 bit 流；`Channel.m` 是信道对象封装；`Slicer.m` 完成采样、抖动和 NRZ/PAM4 判决；`Pll.m` 模拟 forwarded clock 或 CDR 模式下的输入抖动、恢复相位和残余相位。叶子类的共同特点是可以单独执行 `configure()`、`run()` 和 `dump()`，因此不是黑盒函数。

`src/composite/` 存放由多个叶子类组成的复合模块。`Afe.m` 组合 TERM 和 CTLE，并记录 `termOut`、`ctleRaw`、AGC gain 和归一化后的 `ctleOut`；`RawPcs.m` 负责生成测试码型、生成参考 bit、误码注入、保存 TX bit 和 RX bit，并统计每条 lane 的错误数；`TxLane.m` 组合 FFE、Serializer 和 Driver，表示一条 TX lane；`RxLane.m` 组合 AFE、Slicer 和 Deserializer，表示一条 RX lane；`TxSupport.m` 和 `RxSupport.m` 表示 TX/RX 公共支持电路，主要包含 PLL/时钟相关对象；`TxPma.m` 负责组织 8 条 TX lane 和 TX support；`RxPma.m` 负责组织 8 条 RX lane 和 RX support；`D2DPHY.m` 是顶层模型，连接 Raw PCS、TX PMA、8 条 Channel、RX PMA，并提供 `configure()`、`run()`、`dump()` 以及结果汇总接口。

`src/config/` 存放参数和同步桥接。`phyConfig.m` 是寄存器风格的配置入口，`phyConfig()` 返回典型非理想但可工作的 D2D profile，`phyConfig('ideal')` 返回理想 BER=0 profile；典型 profile 包含 8 dB Nyquist 信道损耗、28 dB SNR、轻微 RJ/DJ、轻度 TX FFE、8 dB CTLE 和 forwarded clock。`syncD2DConfig.m` 把 MATLAB 配置发布到 base workspace、Simulink Model Workspace 和 `simulink/d2d_shared_config.mat`；`loadD2DSharedConfig.m` 按“已加载 Simulink 模型、MATLAB base workspace、共享 MAT 文件、默认配置”的优先级读取配置。两者共同实现 GUI 与 Simulink 的参数同步。

`test/` 是自动化验证目录。`test_dsp.m` 验证最基础的 DSP API，包括 0 dB 信道恒等、PAM4 映射、零 tap FFE 和信道 dB 精度；`test_leaf_classes.m` 对各个叶子类执行 configure、run、dump，检查白盒节点；`test_hierarchy.m` 构造完整 x8 `D2DPHY`，验证理想 BER=0 和内部探针；`behavior_tests.m` 验证损耗、CTLE、RJ 和 CDR 的行为趋势，并生成对应 CSV/MAT 结果；`sweep_eq.m` 扫描 TX FFE 和 CTLE 参数，寻找较优均衡组合并检查等效 dB；`run_all_tests.m` 是总入口，执行 T1–T9，生成眼图、bathtub、调制对比、loopback、summary、manifest、JUnit 和 regression MAT 文件。

`gui/` 是 MATLAB 原生 paper GUI。`launchD2DWorkbench.m` 是启动函数，负责加入 `src` 和 `test` 路径并创建 GUI；`D2DWorkbench.m` 是 GUI 主类，左侧显示 VLSI2024 XSR paper 层级树，中间显示可编辑的 paper `d2dCfg` 参数表和 paper actions，右侧显示白盒探针、post-lock 眼图/性能、BER 指标和训练日志。GUI 只提供 `VLSI Typical` / `VLSI Ideal`、Run x8 Link、paper baseline/static/BB-CDR-PI-jitter/adaptation/full regression actions；backend generic profiles 和 legacy tests 仍从 MATLAB 命令行运行。`Apply + Sync` 会把已验证 paper 配置同步到 Simulink，`Load from Simulink` 只接受 paper schema；打开 GUI 或 Run x8 Link 不写正式 paper results。`gui/README.md` 说明 GUI 启动方式、paper 控件和测量边界。

`simulink/` 是独立的框图实现路径，不替换 MATLAB 类模型和 GUI。`buildD2DSimulinkModel.m` 自动生成 Simulink 模型，顶层结构为 `TX Bits → Raw PCS → TX PMA x8 → Die-to-Die Channel x8 → RX PMA x8 → BER Results → RX Bits`；TX PMA、Channel 和 RX PMA 内部使用 Demux/Mux 组织 8 条并行路径。每条 TX lane 展开为 FFE、Serializer、Driver，每条 RX lane 展开为 AFE/TERM、CTLE、Sampler、Slicer、Deserializer。算法 block 使用 Interpreted MATLAB Function 直接调用 `src/dsp/` 中的函数，并通过 `d2dCfg` 读取参数。`D2D_PHY_SI_Simulink.slx` 是已经生成的 Simulink 模型文件；`d2d_shared_config.mat` 是 GUI 和 Simulink 之间的持久化共享配置；`D2D_PHY_SI_Simulink.slx.autosave` 是 Simulink 自动保存文件，如果没有未保存修改，通常可以视为临时文件；`simulink/README.md` 说明模型生成、打开和参数同步方式。

`results/` 只保存测试和 GUI 运行产生的证据，不参与模型计算。`T1_eye_*.png` 是不同调制方式、速率和信道损耗下的 16 组眼图；`T1_eye_metrics.csv` 保存对应 BER 和眼高；`behavior_loss.csv`、`behavior_ctle.csv`、`behavior_rj.csv`、`behavior_cdr.csv` 分别保存损耗、CTLE、RJ、CDR 行为扫描；`behavior_results.mat` 保存行为测试结构化结果；`T3_bathtub.csv` 和 `T3_bathtub.png` 保存经验 bathtub；`eq_sweep.csv` 和 `eq_best.mat` 保存均衡扫描和最优参数；`T6_patterns.csv` 保存码型及误码注入结果；`T7_modulation.csv` 保存 NRZ/PAM4 对比；`T9_loopback.csv` 保存 shallow、serial lane 和 die-to-die loopback 结果。`gui_loss_sweep.csv`、`gui_ctle_sweep.csv`、`gui_rj_sweep.csv`、`gui_cdr_sweep.csv` 和其他 `gui_*.csv` 是 GUI 执行扫描时生成的结果；`summary.csv` 是 T1–T9 总结；`manifest.json` 保存 MATLAB、时间戳和模型说明；`probes.json` 保存白盒探针尺寸；`junit.xml` 供自动化测试系统读取；`regression.mat` 保存完整回归对象和中间结果；`.gitkeep` 只是用于保持空结果目录的占位文件。

整体运行顺序可以理解为：先用 `phyConfig()` 或 `phyConfig('ideal')` 生成配置，再由 `RawPcs` 生成 bit/符号，经过 TX PMA 的 FFE、串化和 Driver，进入 8 条解析 Channel，再经过 RX PMA 的 AFE、CTLE、采样、切片和反串化，最后由 `RawPcs.check()` 对比参考 bit 并计算 BER。`D2DPHY` 是 MATLAB 类模型的顶层入口；GUI 是它的交互操作入口；Simulink 是同一套算法和参数的可视化框图入口；`test/run_all_tests.m` 是自动验收入口。
