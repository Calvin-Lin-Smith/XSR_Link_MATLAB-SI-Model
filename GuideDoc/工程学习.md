# 从零读懂 D2D MATLAB/Simulink 工程

本文是学习路线和源码地图；参数逐项定义见 [参数台账](参数.md)，GUI 回调与测量边界见 [Test 回调契约](Test回调.md)，逐步复现和演示见 [canonical 完整指南](VLSI2024_XSR_SerDes_完整复现与演示指南.md)。

## 1. 先建立正确的边界

工程是 D2D 112G PAM4 的系统级 SI/架构趋势行为模型。它用于理解 TX FFE、解析 IL、AC/CTLE、sampler roles、BB-CDR/PI、BER 和训练之间的因果关系，不是 3nm 晶体管模型、IBIS-AMI、真实封装 S 参数、硅后 sign-off 或功耗分析。

VLSI2024 GUI 是 paper-only：只显示 VLSI Typical/VLSI Ideal、paper 参数表和 paper actions。旧 typical/ideal 与 T1–T9 仍可由 CLI 使用，不应把它们当成 GUI 操作。

## 2. 推荐的从零路线

1. 在 MATLAB R2024b 中将当前目录切到 D2D_matlab_model，加入 src、test、gui 路径。
2. 先用 phyConfig('ideal') + D2DPHY.run() 看清无损、无噪声、无抖动的数据流。
3. 再读 dspPrbs、dspMap、dspFfeVector、dspChannel、dspAcCouple、dspCtle、dspSample、dspSlice。
4. 读 leaf 类的 configure/run/dump：Ffe、Driver、Channel、Term、Ctle、Slicer、Pll、Serializer、Deserializer。
5. 读 composite：RawPcs、TxLane、RxLane、TxPma、RxPma、D2DPHY。
6. 用 phyConfig('vlsi2024_xsr_typical') 运行一次短 debug_link，比较 requested/trained/applied。
7. 再阅读 [Test回调.md](Test回调.md) 的 lock、post-lock、no-lock 和 artifact 边界。
8. 最后才运行 baseline、static、adaptation 或 full regression；需要旧行为时单独运行 run_all_tests。

最小 MATLAB smoke：

~~~matlab
root = pwd;
addpath(genpath(fullfile(root,'src')));
addpath(genpath(fullfile(root,'test')));
cfg = phyConfig('ideal');
phy = D2DPHY('learn_ideal',8);
phy.configure(cfg);
result = phy.run();
disp(result.aggregateBer);
disp(phy.rxPma.lane(1).afe.ctleOut(1:min(16,end)));
~~~

核心对象层级：

~~~text
D2DPHY
├─ RawPcs
├─ TxPma x8
│  ├─ TxSupport → Pll
│  └─ TxLane x8 → Ffe → Serializer → Driver
├─ Channel x8
└─ RxPma x8
   ├─ RxSupport → Pll
   └─ RxLane x8 → Afe(Term → AC pre → Ctle → AC post/AGC)
                    → Slicer(sampler roles) → Deserializer
~~~

VLSI formal path 另外在 RxLane 中使用 dspBbCdr 和 dspPiClock；Tx/Rx support 的 Pll 是 jitter/recovered-clock 行为源，不等同真实 DLL/PI 电路。

## 4. 主数据流：从 bit 到 BER

1. RawPcs.run 根据 pattern 产生 referenceBits；PAM4 由 dspMap 映射成 −3/−1/+1/+3。
2. TxPma.run 对每 lane 依次执行 Ffe、Serializer、Driver。VLSI vector FFE 使用显式 signed offsets/coefficients；Driver 可选 206-level 行为量化与 swing calibration。
3. D2DPHY.run 对每 lane 调用 analytic Channel；若 snr_dB 有限，在 channel output 上按 RMS 加高斯噪声。
4. RxPma.run 由 RxSupport.Pll 生成/处理采样 jitter；TxSupport.Pll 当前没有被 TxPma.run 调用。每个 RxLane 调用 Afe，再依据模式选择 reference alignment、manual phase 或 decision-directed BB-CDR。
5. Afe 暴露 termOut、acPreOut、ctleRaw、acPostOut、ctleOut、levelShiftOut；Slicer 暴露 data、edge、spare 角色输出。
6. RxLane 经过 Deserializer 得到 rxBits；RawPcs.check 的实际签名是 check(rxBits,skipUI)，它使用 RawPcs 对象内部的 referenceBits 作基准。formal paper link 在 D2DPHY.run 内部先按 skipUI 检查，debug_link final pass 再按 berStartUI 重算。

legacy reference-align 会调用 dspAlign 穷举整数 delay 与 sps 内 phase，并使用 txBits；formal VLSI2024 将 model.useReferenceAlign 设为 false，CDR 只读取接收样本和已有 data decision。

## 5. 控制与训练流

### 配置流

phyConfig 返回嵌套 cfg。D2DPHY.configure 将 link、rawPcs、txPma、rxPma、channel 分发到对象；GUI 的参数表只编辑 paperConfigPaths 列出的 paper schema。Apply + Sync 使用默认 modelName=D2D_PHY_SI_Simulink：总写 base/默认共享 MAT，只有 Simulink license 存在且该模型已加载时更新其 Model Workspace；Run x8 Link 只保留内存 requested cfg。

### Run x8 Link

run_vlsi2024_xsr('debug_link',nBits,'Config',cfg) 固定 x8，先用最多 min(nBits,2^14) 的离线 training flow，再重新运行 final x8 link。五个独立 stage 为 startupCalibration、clockTraining、samplerCalibration、ctleTraining、ffeTraining，另有 cdrEnabled 和 postLockWaitUI。

启用 stage 消耗对应 UI budget；禁用 stage 为 skipped_manual_value 并保留用户手动值。trainingEndUI 是 consumedUI 累加，不是 final 数据量。若 CDR 有效，所有 lane 必须 lock；measurementStartUI 取 originalSkipUI 与 latestLockUI+postLockWaitUI 的较大值。所有 eye/BER/margin/probe performance 从该统一窗口开始。

### Adaptation

run_vlsi2024_xsr('adaptation',nBits,'Config',cfg) 生成 RESET、STARTUP_IMPEDANCE_CAL、CLOCK_CAL、INITIAL_EQ_TRAIN、MISSION_TRACK 五状态 trace。扰动包括 TX gain、RX term、channel loss、CTLE drift、DLL/DCC 和 sampler offset；目标是相邻 decision-level margin，不是有限 BER 最小化。

## 6. 为什么这样建模

- 纯 DSP 函数让每个机制可单测；leaf/composite 让输入、输出和内部 trace 可见。
- signed vector FFE 允许 3/6 tap 统一表示，且能把 normalization/current constraint 记录下来。
- analytic IL 先保证 28 GHz 目标插损可校验；没有真实 S 参数时不伪造反射或 MIMO。
- AC coupling、CTLE、level-shift 和 sampler role 分开保存，便于把低频 baseline、均衡和阈值影响区分开。
- BB-CDR/PI 把“无 reference 的决策路径”和“最终 reference checker”分开，避免把 oracle alignment 当成论文 CDR。
- offline training 与 final measurement 分开，避免训练候选或 pre-lock 暂态污染 eye/BER。

## 7. 如何读 probe 与结果

一次对象运行后，先看这些节点：

~~~matlab
phy.txPma.lane(1).ffe.out
phy.txPma.lane(1).driver.txPad
phy.channel(1).out
phy.rxPma.lane(1).afe.termOut
phy.rxPma.lane(1).afe.acPreOut
phy.rxPma.lane(1).afe.ctleRaw
phy.rxPma.lane(1).afe.acPostOut
phy.rxPma.lane(1).afe.ctleOut
phy.rxPma.lane(1).slicer.dataSamples
phy.rxPma.lane(1).slicer.edgeSamples
phy.rxPma.lane(1).slicer.spareSamples
phy.rxPma.lane(1).cdrTrace.piCodeTrace
~~~

debug_link 输出的 Debug.performance.lane(k) 已按 measurementStartUI/sample 裁剪；Debug.fullLockTrace 保存完整 CDR trace；Debug.trainedParameters 保存三态参数表。不要把完整 cdrTrace 的前段当作 post-lock performance。

结果目录中，先读 config.json 与 assumptions.md，再读 baseline_metrics.csv、loss/IL、ffe_3_vs_6、ac_ctle、CDR/PI、adaptation 和 regression_summary。BER 行必须同时看 errors、measured_bits、empirical_BER、seed、ber_upper_95；零误码时 UCB 是 3/N 的有限样本上界，不是无穷长 BER 证明。

## 8. 调试顺序

1. 先运行 Ideal；若 Ideal 失败，检查路径、modulation、sps、FFE offsets/main 和 skipUI。
2. 逐级查看 TX FFE、TX pad、channel、Afe AC/CTLE 和 Slicer data decision input。
3. 若 CDR 无锁，查看 CDR error、transitionTrace、PI code、residualPhaseUI、lockWindow、lockToleranceUI、minTransitions 和 maxCodeSpanCodes。
4. 若状态是 invalid_no_lock 或 invalid_insufficient_bits，不读取 BER/eye 为性能结论；先缩短 nBits 只做 smoke，或修正实际锁定条件。
5. 若 status=debug_no_cdr，检查 cdrEnabled 与 cdrOptions.enabled 的合取，并确认 manualPhaseUI/manualDelayUI。
6. 若 CTLE 请求值不是网格点，查看 requested/applied 和 candidate_4.13；不要把 4.13 当成正式档位。
7. 若共享配置异常，先检查 loadD2DSharedConfig 的优先级和 Model Workspace，再决定是否 Apply + Sync。

## 9. 安全扩展

- 只在新 profile 或明确 paper 字段上增量扩展；保留 typical/ideal 与旧 flat alias。
- 优先复用现有 dsp/leaf/composite，不在 GUI 或 Simulink 复制算法。
- 新增参数同时更新 paperConfigPaths、解析/校验、trainedParameters、结果字段和最小测试。
- 用短 nBits 的 debug_link 或单测验证；确认输出目录和共享快照是否应写，再运行正式 runner。
- 把真实 S 参数、MIMO、晶体管、功耗或协议接口视为独立范围；没有输入数据时只写 limitation，不填猜测值。
